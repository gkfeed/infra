# API contract

Target API contract approved on 2026-09-04. The API implementation must be
integrated with PostgreSQL before it is merged; it will not be deployed as a
SQLite transition release.

| Table | Columns | API access | Owner | Keys |
| --- | --- | --- | --- | --- |
| `users` | `id`, `name`, nullable `hashed_password` | Read; update password hash | API | PK `id`; unique `name` |
| `feed` | `id`, `title`, `url`, `type`, `user_id` | Read, insert, delete | API | PK `id`; FK `user_id -> users.id`; unique `(user_id, url, type)` |
| `item` | `id`, `feed_id`, `title`, `text`, `date`, `link` | Read and delete | Shared: Parser creates, API deletes | PK `id`; FK `feed_id -> feed.id ON DELETE CASCADE` |
| `webauthn_credentials` | `id`, `user_id`, `credential`, `name`, `created_at`, `last_used_at` | Read, insert, update, delete | API | PK `id`; FK `user_id -> users.id` |
| `refresh_tokens` | `id`, `user_id`, `expires_at`, `created_at` | Read, insert, delete | API | PK `id`; FK `user_id -> users.id` |

Integer IDs use `INTEGER GENERATED BY DEFAULT AS IDENTITY`. This lets
applications generate IDs and lets the legacy importer preserve explicit IDs.
User names are non-null and unique. Password hashes may be null for users who
have no password. Feed fields are non-null. A user may add the same URL under
different feed types, but may not repeat the same URL and type. Different
users may add the same URL and type.

Shared parser text columns are non-null. Contract timestamps use
`TIMESTAMPTZ`. WebAuthn credential IDs use `BYTEA`; serialized credential JSON
uses `TEXT` so PostgreSQL preserves the API representation unchanged.

The parser may read feeds and create items. The API may read and delete items.
The parser never deletes items. Deleting a feed cascades to its items in the
database schema.

`deleted_items` is legacy SQLite import data, not a table in the canonical
`public` schema. The infra-owned importer stages tombstones temporarily in
PostgreSQL, validates ownership, deletes matching imported items, reports
invalid tombstones, and removes the staging table before cutover.

All legacy data conversion belongs to the infra-owned importer. This includes
converting any remaining plaintext SQLite passwords into the target
`hashed_password` representation. The API does not run data migrations at
startup.

The canonical token table is `refresh_tokens`. SQLite `itemhash` and
`auth_refresh_tokens` are legacy input and are not PostgreSQL tables.
